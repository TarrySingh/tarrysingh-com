# 09 · Deployment

Short doc. Hosting, domains, analytics, monitoring, IP.

## Hosting

- **Vercel**, free tier sufficient at launch volume.
- Production branch: `main`. Preview deploys on every PR.
- Region: `fra1` (Frankfurt) primary — closest to the EU audience.
- Environment vars: none required for v1.0. If/when contact form added, store SMTP credentials in Vercel project settings (never commit).

## Domain & DNS

Decide before launch (Tarry to confirm):

1. **`tarrysingh.com`** — full personal-brand carrier. Subroutes for `/memphis`, `/symphony`.
2. **`synapticcartography.tarrysingh.com`** — series-as-subdomain. Reads more like an institute.
3. **`synapticcartography.com`** — buy the standalone domain. Strongest series identity, weakest personal-brand carrier.

Recommendation: **option 1** for v1.0, with option 3 reserved for future expansion.

DNS:
- Apex `A` → Vercel.
- `www` `CNAME` → apex, redirect to apex.
- `MX`: keep existing email setup.
- `TXT` for SPF/DMARC: confirm with Tarry's existing email provider.

## TLS

Automatic via Vercel. Enforce HTTPS, HSTS preload eligible.

## Analytics

Pick one, install neither until launch day.

- **Vercel Analytics** (built-in, no cookie banner needed, GDPR-clean).
- **Plausible** (self-hosted or cloud — also cookie-less). Slightly richer.

Do **not** install Google Analytics. Tarry's audience does not consent to it casually, and the cookie banner would compromise the site's tone.

## Monitoring

- **Vercel deployment logs** — sufficient for v1.0.
- **A single Playwright smoke test** in GitHub Actions running on every PR, walking `/` → `/memphis` → `/symphony` → `/contact`. Failure blocks merge.
- **Uptime check**: free Better Uptime monitor on the apex domain. Email alerts.

## SEO

Minimal but precise.

- `<title>` per page: `MEMPHIS — Synaptic Cartography` etc.
- `<meta description>`: the italic close caption of each page.
- `og:image`: server-rendered via `app/[project]/opengraph-image.tsx`. Built from the static plate PNG.
- `robots.txt`: allow all. No `noindex` anywhere on the canonical site.
- `sitemap.xml`: auto-generated by `next-sitemap`.
- Structured data: `Article` schema on each proposal page.

No SEO spam. The audience finds this site via direct links and word-of-mouth, not via Google.

## Performance budget enforcement

Add a Vercel "Speed Insights" tab; pin the budgets from `03-tech-stack.md` to PR comments. Anything that regresses LCP by more than 100ms blocks merge unless explicitly justified.

## Backups

- Repo is the source of truth. Push to GitHub on every change.
- Vercel keeps deployment history for 30 days.
- Mirror the repo to a private GitLab or Bitbucket once a week (GitHub Action, scheduled). Insurance only.

## IP & legal

- `LICENSE` file at the repo root: **All rights reserved** (proposals are pre-publication; standard OSS licence would over-permit).
- A short `IP.md` in the repo root summarising what is © T. Singh and what is © consortium-partner-X.
- The site's footer carries a small mono mark: `© T. Singh, 2026. Consortium materials under controlled disclosure.`
- Calendly meetings opt the attendee into a brief NDA reference (added to the meeting description, not enforced as a click-through — keep the tone right).
